# beancount-parser

A TypeScript parser for the [Beancount](https://beancount.github.io/) plain text accounting format, built with ANTLR4.

## Features

- Full Beancount syntax support
- Strongly-typed TypeScript models
- ANTLR4-based grammar for robust parsing
- Comprehensive unit tests

## Installation

Workspace package of the obsidian-beancount monorepo (not published). Depend on it from another workspace package:

```json
"dependencies": { "@repo/beancount-parser": "workspace:*" }
```

## Usage

```typescript
import { BeancountParser } from '@repo/beancount-parser';

// Parse Beancount content
const beancountContent = `
2023-01-15 * "Grocery Store" "Weekly shopping"
  Assets:Checking    -85.40 USD
  Expenses:Food       85.40 USD
`;

const result = BeancountParser.parse(beancountContent);

// Access the parsed data
console.log(result.directives.length); // 1
const transaction = result.directives[0];
console.log(transaction.payee); // "Grocery Store"
console.log(transaction.postings.length); // 2
```

### Errors

`parse()` never returns a partially recovered file. Any lexer or parser error throws a `BeancountSyntaxError` listing every problem in source order. If the syntax is valid, the same error lists every value error the grammar cannot reject, as upstream Beancount does: invalid dates (`2022-02-30`), duplicate metadata keys or cost components, `1/0` and other non-finite numbers, popping an absent tag, and tags still pushed at end of file:

```typescript
import { BeancountParser, BeancountSyntaxError } from '@repo/beancount-parser';

try {
  BeancountParser.parse('2022-01-01 open\n');
} catch (e) {
  if (e instanceof BeancountSyntaxError) {
    console.log(e.errors); // [{ line: 1, column: 15, message: "missing ACCOUNT at '\\n'" }]
  }
}
```

`line` is 1-based, `column` 0-based. Each directive and posting also carries a `location` with the same convention.

## Data Model

The parser generates a strongly-typed object model with classes for all Beancount directives:

- `Transaction`
- `Balance`
- `Open`
- `Close`
- `Price`
- `Note`
- `Document`
- `Event`
- `Commodity`
- `Custom`
- `Option`, `Plugin`, `Include`

Postings keep their flag, cost (`amount` per-unit, `total`, `date`, `label`, `merge`) and price annotation. Amounts with the number or currency left out for interpolation are `IncompleteAmount`. `pushtag`/`poptag` tags are added to the transactions between them; `pushmeta`/`popmeta` are accepted but not applied yet.

## Development

### Prerequisites

- Tests run on [Bun](https://bun.sh) (`bun:test`); `pnpm install` provides it via the `bun` dev dependency
- No Java needed: the parser is generated by [antlr-ng](https://github.com/mike-lischke/antlr-ng) (dev dependency) and runs on the [antlr4ng](https://github.com/mike-lischke/antlr4ng) runtime

### Setup

```bash
# From the monorepo root
pnpm install

# Regenerate src/parser/ after editing src/grammar/Beancount.g4
# (generated TypeScript is committed)
pnpm --filter @repo/beancount-parser generate

# Run tests
pnpm turbo test --filter=@repo/beancount-parser
```
